# B10 Hosted MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve Keystone's six existing graph tools publicly over HTTPS at `/mcp`, with tenant admission and 30 tool-call attempts per IP per minute, without exposing any action tool.

**Architecture:** Build a Streamable HTTP application from the existing `api.mcp_server.graph_tools`, not the seven-tool `mcp`. A small HTTP-only ASGI admission wrapper validates public tenants and tool names and applies an in-process rolling-window limiter before delegation; it never changes the shared server or implementations. Mount the guarded transport beneath the existing FastAPI lifecycle and expose it only through Caddy.

**Tech Stack:** Python 3.11+, FastAPI `0.143.2`, standalone FastMCP `4.1.0`, MCP `2.3.0`, Starlette `1.8.0`, httpx `0.28.1`, pytest `8.4.2`, existing FalkorDB client and Caddy `2.8.4`; no new dependencies.

**Spec:** `docs/spec.md`, especially sections 5, 7, 9 and 13; `docs/tasks.md` B10; ownership and scope rules in `CLAUDE.md`.

## Global Constraints

- “Exposes the six read-only graph tools; `apply_triage` is never exposed over HTTP.”
- “Public tenants only, no auth (the data is public), with a per-IP limit of 30 calls a minute.” Here a call means a `tools/call` attempt, not an HTTP request or an initialize/list operation.
- “The README gives a copy-paste config for MCP clients that support remote servers, plus three example prompts.”
- “Every tool returns its evidence.” Preserve the existing `ToolResult`, schemas, defaults, Cypher and parameter handling without translation.

## Review Focus

1. Direct calls to hidden/unknown tools, including `apply_triage` with either dry-run value, must execute nothing (Task 1).
2. A configured but non-public tenant, malformed tenant value, or mismatched Settings/environment must fail before embeddings or graph access (Task 1).
3. Batch payloads and tool-call notifications must not bypass quotas or accidentally execute actions; preserve protocol response semantics (Task 2).

### Decisions (user-approved ingress; remaining implementation choices by the planning agent)

- Add `PUBLIC_MCP_TENANTS`, distinct from `TENANTS`; absent/blank means no public tenants (fail closed). *(Superseded in review: blank now means every tenant in `TENANTS`, since all are public orgs; an explicit value must be a subset. `validate_public_tenants` was removed; `load_settings` does the subset check.)* Deployment explicitly sets `falkordb`, or `falkordb,pallets` after B9. The user approved both configured demo tenants as public; the separate allowlist prevents a later private tenant from becoming public accidentally. Validate each public slug against configured tenants and the existing tools' environment at startup; disagreement is a startup configuration error, never an environment mutation. No tenant-file schema change is needed.
- Use stateless Streamable HTTP with JSON responses, not legacy SSE and not a second server/process. One shared rolling window spans all sessions, six tool names and public tenants. A restart clears it; horizontal scaling or multiple workers is unsupported already by the webhook design.
- **User-approved ingress:** Caddy faces the internet directly, with no CDN, load balancer, or other proxy before it. Point the API domain's DNS record at the VM; if Cloudflare manages DNS, use **DNS only** (grey cloud). Expose Caddy on ports **80/443**, keep API **8000** and FalkorDB **6379/3000** private, and let Caddy manage HTTPS certificates. The web app remains on Vercel. A later proxy/CDN requires a separately reviewed client-IP trust design.
- Caddy overwrites `X-Keystone-Client-IP` with `{remote_host}` (the actual socket peer, not a forwarded-header value). The wrapper accepts exactly one syntactically valid IP in that header, canonicalized with stdlib `ipaddress`; missing, repeated, comma-separated or malformed values fail closed with `503`. This header is trustworthy only because the API is unreachable publicly and Caddy is the sole public ingress. Do not trust client `Forwarded`, `X-Forwarded-For`, `X-Real-IP`, MCP session IDs or tenant values for quota keys. Stop for a revised trust design if deployment differs from the approved direct ingress.
- Quota counts every valid JSON-RPC `tools/call` envelope admitted at the HTTP boundary, including unknown tool names, forbidden tenants, argument errors and failed executions. The 31st attempt in a rolling 60 seconds executes nothing. Other protocol methods and malformed envelopes do not consume tool quota. No retries/refunds after a tool error.
- Reject every JSON array as unsupported batching with HTTP `400`, JSON-RPC `-32600`, `id: null`, and zero tool execution/count. Current Streamable HTTP does not require batch execution. A valid tool-call notification (no `id`) consumes one attempt but never executes; answer `202` with an empty body. At quota exhaustion it still executes nothing and returns HTTP `429` with an empty body (no JSON-RPC notification response).
- For requests with an `id`, exhausted quota returns HTTP `429`, `Retry-After` (ceiling of seconds to the oldest retained attempt's expiry, minimum 1), and JSON-RPC error `-32000` / `"Tool call rate limit exceeded"` with the original ID. Unknown tools return `-32601`; missing/non-string/non-public tenants return `-32602` / `"Public tenant unavailable"`. No enumeration of private tenant names or raw exception details. SDK-native validation handles remaining argument/schema errors after admission.
