# B2 Fixture API Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose spec section 9's API surface through validated fixture-backed routes, explicit deferred integration endpoints, and exact-origin CORS.

**Architecture:** Extend B1's FastAPI app with small routers and a read-only fixture loader. Agent-facing routes stay together in `api/routes/agent.py` for A's Saturday takeover; graph, action and tenant routes remain B-owned. No database, LLM, GitHub or MCP execution is introduced by this shell.

**Tech Stack:** Python 3.11+, FastAPI/Pydantic, pytest, httpx; existing B1 container stack.

**Spec:** `docs/tasks.md` B2/T0; `docs/spec.md` sections 5, 7–9, 13; `CLAUDE.md`; approved `docs/superpowers/plans/2026-10-14-b1-b3-contract-proposal.md`.

## Global Constraints

- “CORS allows the Vercel domain and localhost only.” Exact approved origins; no wildcard.
- “Stable keys, not internal ids.” “Lists are never null.”
- “Sandbox only.” Fixture mode never writes, even for `dry_run=false`.
- “No agent frameworks.” No graph/agent implementation in B2.
- T0 models/TypeScript/fixtures require both owners' agreement. B2 consumes them, never silently replaces them.
- No commits or branch commands; no product code before kickoff. Owner ticks B2 only after actual acceptance output.
- B2 may initially create `api/routes/agent.py` per its task; A takes over Saturday. All other A implementation files remain untouched.

## Review Focus

- Unknown tenant/run: 404, never another tenant's fixture data.
- Invalid or ambiguous requests: 422 rather than guessing the intended mode.
- Disallowed/missing CORS origin: no permissive allow-origin header.
- Explicit live apply in fixture mode: refused, with zero network writes.
- Missing/corrupt fixtures and deferred endpoints: clear errors, not fabricated success.

**Interfaces:** `create_app(settings: Settings | None = None, fixture_store: FixtureStore | None = None) -> FastAPI`; exported `app = create_app()`. Each router exports `router: APIRouter`. Use approved request and response models/aliases from the proposal:

- `agent.py`: `triage(tenant: str, request: TriageRequest) -> TriageResult`, `list_runs(tenant: str, limit: int = 20) -> RunsResponse`, `get_run(tenant: str, run: UUID) -> ToolResult`, `feedback(tenant: str, run: UUID, request: FeedbackRequest) -> FeedbackResult`, `ask(tenant: str, request: AskRequest) -> AskResult`.

- `graph.py`: `path(tenant: str, from_key: str, to_key: str) -> ToolResult`, aliases `from`/`to`; `subgraph(tenant: str, keys: str) -> Subgraph`; `stats(tenant: str) -> Stats`.
